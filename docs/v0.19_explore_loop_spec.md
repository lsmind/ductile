# v0.19 探索环规格（explore-then-freeze）

状态：提案（用户定调 2026-09-15，源自 RSIAgent 对照）。
姊妹篇：v0.18 上下文协商（declare-then-run）。实现排 v0.18.16 实证轮之后。

## 1. 动机与定位

ductile 的 L4 沉淀线（harvest/learn/incident/patch）是**被动**的：只从已发生的
runs 里归纳。没有任何机制主动生成「接下来该探什么」。RSIAgent（arXiv:2609.15364）
实证了主动探索环的价值：curriculum（出题）→ actor（执行）→ verifier（独立验证）
→ memory（沉淀复用），training-free，纯结构层，GLM-5.3+Kimi-K3 借此反超 GPT-6。

**ductile 已有它 70% 的零件**：foreach 并行（波）、独立 judge（v0.11 裁判分离）、
incident/hyper/契约卡（memory）、errflow（失败分类）。缺的 30% 是驱动循环——
2026-09-15 自审轮就是一次手工人肉 BRS+DRS（第一轮 4 模块并行宽审、第二轮
executor/egraph/errflow 深挖、三实锤固化进 skill），证明原语够用，缺的是
引擎一等公民化。

### 设计红线（用户宪法级）

- **裁判确定性优先**：验证「有没有错」永远优先确定性信号（exit code / 文件内容
  / AST 输出 / parse 结果）。LLM 只答「为什么」+ 端到端复核。RSIAgent 用 LLM
  verifier 是因为 GUI 反馈弱；ductile 环境反馈强，照搬反而是降级。
- **循环在引擎不在模型**：与 v0.18 同款。curriculum 出题、预算控制、收敛判定
  全在 Rust 侧，可单测、可进回归门禁。模型每轮无状态。
- **fail-closed**：预算耗尽 / 裁判不可判 / DSL 片段非法 → 终止本轮，不静默继续。
- **零默认面**：不写 explore 管线就零变化（与 negotiate 默认关同款纪律）。

## 2. 三角色映射

| RSIAgent | ductile 落点 | 说明 |
|---|---|---|
| Curriculum | `[agents.curriculum]`（新 LLM 角色） | 读 memory 概况+缺口，产出探针任务（DSL 片段或 plan 文本） |
| Actor | 现有 executor（run/llm/foreach） | 无改动。探针任务就是普通管线 |
| Verifier | 确定性裁判 proc + LLM 复核 | 确定性层先判（exit code/文件/AST），不可判才升 LLM |
| Memory | incidents + hyper + guide 冻结 | 探索期可变，收敛后冻结，测试期只读检索 |

### curriculum 输出契约

```json
{"tasks": [{"id": "probe-x", "goal": "验证 foreach+llm 跨行 prompt 依赖边",
            "kind": "broad|deep", "plan": "<DSL 片段或自然语言步骤>",
            "judge": "<确定性判据描述>"}],
 "gap": "本轮探针针对的记忆缺口",
 "stop": false}
```

- `judge` 必须落到**确定性判据**（grep 什么/exit code 期望/parse 输出含什么）。
  curriculum 只描述判据，不执行——执行走独立 verifier proc。
- `stop=true` = curriculum 认为继续探索边际收益不足（RSIAgent 同款：成功不自动
  终止，由 curriculum 复盘决定）。引擎仍有硬预算兜底。
- 硬错误：tasks 空 + stop=false（要不出题又不说停 = 违约）。

## 3. 两阶段语义

### BRS（宽）——并行波

```
wave: curriculum 出 N 题(默认 4, 可配) → foreach 并行执行+确定性裁判
      → 结果回灌 curriculum → 下一 wave
预算：波间检查（不打断进行中的波），默认 8 波（RSIAgent 同款 nominal budget）
```

### DRS（深）——串行递进

```
loop: curriculum 基于 memory 挑一个最可能暴露隐藏约束的任务
      → 执行 → 确定性裁判 → 固化(incident/patch/hyper) → 下一题
终止：curriculum stop=true 或硬预算（默认 12 步）
```

阶段切换：BRS 收敛（curriculum stop 或预算尽）→ DRS。两阶段都可单独关闭
（`stages="brs"` / `"drs"` / `"brs,drs"`，默认全开）。

## 4. 探索驱动器（引擎侧，Rust）

新 L4 模块 `explore.rs`（结构经验层，与 harvest 平级）：

```rust
pub struct ExploreBudget { pub waves: usize, pub deep_steps: usize }
pub enum ExploreStop { Budget, CurriculumStop, FailClosed(String) }

pub fn run_explore_loop(cfg: &ExploreConfig, ctx: &ExploreCtx)
    -> ExploreReport
```

- 探针执行 = 现有 executor 跑临时管线（DUCTILE_DATA 隔离，不污染真库）。
- **固化三通道**（复用现有表，不加新表）：
  1. 确定性失败（预期 fail 却 pass / 反之）→ incident（带 action-condition-
     consequence 三元组 schema，见 §6）
  2. 新可复用结构（同构 proc 对）→ compositions（harvest 线现成）
  3. LLM 复核发现的行为解释 → patch 流程（tentative，canary 门禁照旧）
- **ExploreReport** 落 runs 表（管线名 `explore:<topic>`），含每 wave/step 的
  题目、判据、结果、固化清单。审计面与 regcheck3 同构。

### CLI 面

```
ductile explore <pipeline> "topic"          # 全环（BRS→DRS→冻结报告）
ductile explore <pipeline> "topic" --drs    # 只深探
ductile explore --report <id>               # 回看报告
```

零 DSL 面（与 errflow 同款裁定）：不新增 .pipeline 语法，curriculum/judge 通过
config.toml agents 引用——探索环本身不是用户管线的一部分，是引擎对管线的加工。

## 5. 记忆冻结（freeze）

探索收敛后：

- ExploreReport 中被判「稳定复用 ≥3 次」的沉淀 → guide 字段自动生成候选，
  进 `[agents.x] guide` 维护流（人审后生效——制度>自觉，不静默改 agent 配置）。
- 冻结态 = 该 topic 的 explore 报告标记 frozen；后续 runs 只读引用，不再滚动。
- 与 auto-prompt 的关系：注入的「历史统计」段继续滚动；「冻结记忆」段从
  ExploreReport 检索（≤3 条，与 incident 指针卡同款 pull 模型）。

## 6. incident 卡 schema 强化（action-condition-consequence）

现有 incident：id + 信号 + 证据摘要。升级为三元组：

```
action:    foreach(source=@x) 且 source 名在消费者后（字典序）
condition: v0.18.7 前引擎 / 并行调度
consequence: foreach source not found 炸（声明序不保证执行序）
evidence:  探针 probe-x（ExploreReport #12），复现命令
status:    confirmed
```

可检索性更强，与认知规格五分类归因闸（环境/上游投毒/描述错/能力不足/漂移）
直接对齐——consequence 即归因闸的输入信号。向后兼容：老卡无三元组字段照常
注入，检索时降级为全文匹配。

## 7. 验收门禁（fail-closed）

1. **零变化门禁**：不带 explore 的现有 selftest 全绿（443+）。
2. **探针门禁**：`ductile explore` 在沙箱 topic 上完整走通 BRS≥2 波 + DRS≥2 步，
   ExploreReport 落库，固化清单非空。
3. **curriculum 违约门禁**：tasks 空 + stop=false → 硬错误（探针可注入 mock）。
4. **预算门禁**：预算耗尽必终止，report 标 Budget 而非静默成功。
5. **隔离门禁**：探针执行全部 DUCTILE_DATA 隔离，真库 runs/incidents 不变。
6. **冻结门禁**：frozen 报告的二次检索不触发任何写。

## 8. 实施切分

| 期 | 内容 | 验收 |
|---|---|---|
| P0 | curriculum agent 契约 + explore.rs 驱动循环 + ExploreReport 落库 | 门禁 1-4 |
| P1 | 固化三通道接线（incident 三元组/compositions/patch） | 门禁 2 固化清单非空 |
| P2 | freeze + guide 候选生成（人审流） | 门禁 6 |
| P3 | 自举：用 explore 环审 explore 环（本规格实现完的第一个用户） | 自审轮三实锤复现 |

P3 是关键验收：**探索环的第一个探索对象是它自己**——今天上午手搭的自审轮
（BRS 4 模块宽审 + DRS 大模块深挖）必须能被 explore 环自动复现出同等级发现，
否则就是「数据穿引擎但环空转」（mingli v1 教训：结构利用判据=拆掉某环，
运行行为可观察地变化）。
