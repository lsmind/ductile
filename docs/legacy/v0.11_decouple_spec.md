# v0.11「裁判分离」实施规格（2026-09-05 定稿）

目标：评价指标机制与流程描述彻底分离。`.pipeline` 只描述流程（谁做什么、备选路径、数据流），
评价（权重、cost、严格度）独立在 `.eval` 策略文件，运行时 `--policy` 挂载。
原则：不能又当运动员又当裁判——流程不自带判罚，裁判不参与生产。

## 用户裁定的两点（必须遵守）
1. cost 两形态：直接数值，或测试方法 `measure("脚本路径")` 直接链接测试脚本。
2. 谓词层不保留：`.check()`/`.ensure()` 退役，质量门槛由独立 judge proc + `.when()` 路由承担。

## 改动清单

### 1. ast.rs — 新增 Policy 与 CostSpec
```rust
pub enum CostValue { Direct(f64), Measure(String) }  // Measure = 测试脚本路径（可含 {topic} 占位符）
pub struct CostSpec { latency: Option<CostValue>, risk: Option<CostValue>, tokens: Option<CostValue>, money: Option<CostValue> }
pub struct Policy {
    pub weights: Weights,                       // 复用现有 Weights
    pub costs: HashMap<String, CostSpec>,       // key = "proc.impl"
    pub fail_closed: bool,                      // 默认 true
}
```
`Cost`（f64 已解析值）保留，作为解析后的产物。加 `CostSpec::resolve(script_runner) -> Cost`。

### 2. parser.rs — 新增 parse_policy + 旧语法降级
新文件格式 `.eval`（行式，# 注释，容忍空行）：
```
# policies/default.eval
weights latency=0.001 risk=10.0 money=1.0 tokens=0.0001
fail_closed = true
render.sdxl   cost latency=measure("/abs/path/bench_sdxl.sh") risk=0.05
render.flux   cost latency=120.0 risk=0.01
fetch.web     cost latency=measure("/abs/bench_web.sh {topic}")
```
解析规则：`weights` 行 → Weights；`fail_closed` 行 → bool；其余行 `<proc>.<impl> cost <field>=<value>...`。
值语法：纯数字 → Direct；`measure("...")` → Measure。
`.pipeline` 侧：
- `.cost(...)` → 打印 warning `[v0.11] .cost() 已退役：评价移入 .eval 策略文件 (--policy)，此声明被忽略`，解析继续（cost 用 default）。
- `.check(...)` / `.ensure(...)` → 同样 warning + 忽略（谓词层退役，不炸旧管线）。
- `.when(...)` 保留（路由语义）。
- `.plan()` 内非 `name ->` 条目（weights 幽灵 impl 陷阱）→ 硬错误，提示正确语法。

### 3. executor.rs — 测量、fail-closed、退役
a) **cost 解析（排序前）**：对 policy 中每个 CostSpec 的 Measure 项：
   - 查缓存表 `cost_cache(proc,impl,field)`，TTL 内直接用；
   - 过期/无记录则执行脚本：`sh -c "<script>"`，`{topic}` 替换为 pipeline topic；
     取 stdout 第一个浮点数（正则 `[0-9]+\.?[0-9]*`）；超时 60s；执行失败 → 该 impl 视为 cost 未知，
     用 `Cost::default()` 兜底并 warning（不 crash，但排序降到已知 cost 之后——实现上给未知 cost 加罚项即可）；
   - 结果写回 cost_cache（value + measured_at unix ts）。
   解析优先级：实测（缓存新鲜）> Direct 声明 > default。
b) **排序权重**：`Weights` 改为从 Policy 取（无 --policy 时用引擎 default，行为与 v0.10 相同）。
c) **run_checks 退役**：删除 executor.rs:255 调用点与 run_checks/eval_cond 中谓词层
   （procs 的 checks 字段若还在 AST 就不再求值）。proc 结果直接透传。
d) **.when fail-closed**：`.when(@x.field op N)` 中字段缺失/非数值/引用 proc 不存在 → 该 impl 本轮
   视为「条件不成立」跳过（触发降级到下一 impl），并 stderr warning；这不是静默放行。
e) **<noop> 硬错误**：未知函数不再返回 `<noop: f>` 假成功，改为 Err，正常触发 impl 降级。
f) **latency 实测落库**：exec_proc 内 `Instant::now()` 包住 impl 执行，结束时算 ms 写入 runs.latency_ms
   （替换硬编码 0）。这是后续「实测 EMA 排序」的数据地基，本次先保证数值真实。
g) **est_loss_v0**：移除（连同死参数引用），排序中 rd 项删除；README/SPEC 对应段落同步删。

### 4. cli.rs — --policy 参数
`ductile run x.pipeline "topic" --policy policies/default.eval [-- key=v]`。
cmd_run 增加 `Option<PathBuf>` 穿线到 executor。`ductile check` 同样接受 --policy 做 .eval 语法校验。

### 5. db.rs — cost_cache 表
```sql
CREATE TABLE IF NOT EXISTS cost_cache (
  proc TEXT NOT NULL, impl TEXT NOT NULL, field TEXT NOT NULL,
  value REAL NOT NULL, measured_at INTEGER NOT NULL,
  PRIMARY KEY (proc, impl, field));
```
TTL 常量放 executor（默认 86400s）。加读写两个函数。
